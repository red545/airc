## Scope and evidence rules

The target is the owner's **full Arc feature parity**, not the old v1 minimum. Therefore Easels are **in scope and missing**: a browse-only canvas exclusion in spec §2.17 cannot satisfy this request. Notes, shared Spaces, rich previews, and Max are also in scope even where old prose defers them. Deprecated GitHub previews and the legacy Boost builder are excluded; GitHub Live Folders and current Boosts replace them. Platform ports, Arc's proprietary account/referral business and internal engineering tools are explicitly inventoried as out of scope. Arc account infrastructure need not be cloned, but its user-visible sync/sharing outcomes do.

“Done” below certifies only the narrowly named row: implementation plus a matching existing check or user document. Adjacent missing subfeatures have separate rows; a family with any partial/missing row is **not completely done**. “Partial” means an explicit behavioral difference or an unclosed acceptance gate, specified in the next column. “Missing” means the named user-facing route was not found, including where an engine primitive might exist. “Out of scope” is an explicit decision, never a disguised backlog. S is roughly a few hours, M one focused agent-night, L needs decomposition or an external dependency. Sizes are estimates, not commitments.
