# Review of Chromium 156.0.8078.114

Reviewed 2026-11-23. Keep Airc at **156.0.8078.109**. The .114 changes do not
apply to Airc's shipped Variations configuration, and the .114 source branch
omits four fixes present in .109. No engine or profile migration is needed.

## Upstream branches

[The release post](https://chromereleases.googleblog.com/2026/11/extended-stable-update-for-desktop_01590513949.html)
announces .114 for Mac Extended Stable but has not yet published its security
list. No CVE applicability or absence of exploitation is inferred from that omission.

The [forward log](https://chromium.googlesource.com/chromium/src/+log/156.0.8078.109..156.0.8078.114)
has five commits: hybrid PQ Variations seed signatures/key rotation, disabling
VariationsService's HTTP fallback, two version changes and branch dependency
metadata. Its head is `ea19f9737303a76e07b53c6a1eec43355aca3b1d`, on branch
`8078_108`, branched before the .109 fixes.

The [tag diff](https://chromium.googlesource.com/chromium/src/+/156.0.8078.109..156.0.8078.114)
and [reverse log](https://chromium.googlesource.com/chromium/src/+log/156.0.8078.114..156.0.8078.109)
show these .109 fixes absent from .114:

- `f8ec2e9b4054b80e455132faba2ce1a3548be61b`: asynchronous FidoHidDevice error callbacks, preventing a use-after-free write.
- `3455b06a0a5a22f5aa252b6fc536fb654c7cc991`: MediaPermissionDispatcher use-after-free fix.
- `6b1e43fabf5b029b8ef99fac9cc6f9c7a8a96cd8`: navigation reentrancy and document identity guards.
- `efc0bca6e36fcf74779f47922a3be96ec47af754`: animation cancellation guards during style/update iteration.

The Dawn revision also moves backwards from `d2c1eac2db6cc83aa0a38c99239af77a14abf7e7`
to `68b5c1f3f2fc6ccacf7a9cc0cbea0d2b6805ebfa`. A higher version number does not
establish that a release contains all the fixes in the current pin.

## Applicability to shipped Airc

Airc does not fetch Google Variations seeds in its shipped configuration:

1. The qualified official engine's generated `build/branding_buildflags.h` has
   `GOOGLE_CHROME_BRANDING=0`. Official PGO/ThinLTO optimization is independent of
   Google branding; both Airc build variants use Chromium branding.
2. In .109's [`VariationsService::IsFetchingEnabled`](https://chromium.googlesource.com/chromium/src/+/156.0.8078.109/components/variations/service/variations_service.cc),
   the unbranded branch returns false unless `--variations-server-url` or the
   internal test override is present. Desktop startup checks this before starting
   the fetch scheduler or initializing its server URLs. Google URL constants are
   compiled into the service, but are not activated in the shipped configuration.
3. `engine/core/airc_main_delegate.cc` calls `ConfigureBackgroundServices` before
   Chrome startup. `quietVariations` defaults on (`airc_launch_switches.cc`),
   adding `--disable-field-trial-config` and `--disable-variations-seed-fetch`.
   Airc's launcher, engine hooks and import paths supply no variations server URL
   or seed. Imports read source Local State profile metadata and import typed
   browsing data; they do not copy its Variations Local State or SeedFile.
4. Mac [`ChromeVariationsServiceClient::TakeSeedFromNativeVariationsSeedStore`](https://chromium.googlesource.com/chromium/src/+/156.0.8078.109/chrome/browser/metrics/variations/chrome_variations_service_client.cc)
   returns null. There is no mobile-style first-run seed in this Mac path.

The service is still compiled and constructed. This finding is **not** a claim
that seed handling is unreachable under every developer configuration:
`--variations-server-url` explicitly enables unbranded fetching (the disable-fetch
switch is checked only in the Google-branded branch). A manually provided test
seed or an externally preseeded Local State can also be consumed by
`VariationsFieldTrialCreator::CreateTrialsFromSeed`. Such overrides and manually
copied browser data are outside this shipped-configuration review. Reassess before
introducing any seed source, changing branding, or enabling these paths.

The two .114 security-relevant commits protect seed verification and seed
transport. With no configured seed source/fetching in normal Airc operation,
backporting them is not required for the shipped configuration. Retaining .109
preserves its UAF/navigation fixes and newer Dawn.

## Watcher handling

`infra/chromium/reviewed-releases.json` records this exact exception. It is bound
to the .109 pin, .114 upstream commit, clean engine tree and release-post URL and
content hash. The watcher keeps both version numbers visible, labels the gap
`reviewed-not-applicable`, sets `update_required=false`, records this reason in
`state.json`, and removes only the non-actionable update brief.

A newer Extended tag, different pin/engine tree/tag revision, changed or missing
post, security-fetch error, or active-exploitation evidence reopens review. The
exception does not turn .114 into a shipped version and does not suppress future
tags. Continue the existing six-hour watcher and check for a superseding tag that
contains both lines of fixes.
